# Design Critique

## Framework

1. **First impression (2 seconds)**: What draws the eye? Is the purpose clear?
2. **Usability**: Can the user accomplish their goal? Is navigation intuitive?
3. **Visual hierarchy**: Reading order, emphasis, whitespace.
4. **Consistency**: Adherence to the design system. If the project has a design-system doc (e.g. `design-system/DESIGN.md`), check tokens, components and content rules against it.
5. **Accessibility**: Contrast, touch targets, readability.

## How to give feedback

- Be specific: "The CTA competes with the nav", not "the layout is confusing".
- Explain why, and link it to a design principle.
- Suggest alternatives.
- Acknowledge what works.
- Match the stage: exploration is not final polish.

## Output

A Markdown table with Finding / Severity / Recommendation columns, followed by a Priority recommendations section.
