# Decisions

Short records of project-level choices. Newest at the bottom. Change a decision by adding a new entry that supersedes the old one.

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                                                                             | Why                                                                                                                                                                                                                                         |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D01 | **Monorepo: pnpm workspaces + Turborepo, TypeScript strict.**                                                                                                                                                                                                                                                                                                                                                                        | Two apps and a worker share tokens, components, schemas and the database layer. Turbo caches builds and runs tasks per package.                                                                                                             |
| D02 | ~~Superseded by D21.~~ **Two Next.js (App Router) apps: `apps/web` (static export) and `apps/app` (authenticated).**                                                                                                                                                                                                                                                                                                                 | The marketing site needs static HTML, metadata, OG tags and a sitemap. The app needs server route handlers next to the UI. One framework for both keeps `packages/ui` simple. Supersedes the earlier "Vite + React" choice for the website. |
| D03 | **Design system v2 for both apps.** `prototype/design-system/tokens.css` becomes the Tailwind v4 theme, with the default palette removed.                                                                                                                                                                                                                                                                                            | The brief makes v2 the target. Removing the default palette means colours or sizes outside the tokens can't be used by accident. `compat.css` is used only as a rename map and is not shipped.                                              |
| D04 | **Postgres + Drizzle.**                                                                                                                                                                                                                                                                                                                                                                                                              | Typed schema and plain SQL migrations. Runs on any managed Postgres in the cloud or in docker compose locally.                                                                                                                              |
| D05 | **Queue: pg-boss.**                                                                                                                                                                                                                                                                                                                                                                                                                  | The queue lives in Postgres, so there's no Redis to run locally or pay for in the cloud. The volume (roughly 100 users, hourly/daily/weekly refreshes) is well within its range.                                                            |
| D06 | **Auth: Better Auth.** Email + password, 6-digit email-code reset, Google sign-in.                                                                                                                                                                                                                                                                                                                                                   | Covers every flow in `prototype/Auth.dc.html` and has a Drizzle adapter.                                                                                                                                                                    |
| D07 | **Onboarding: port only the 6-step flow inside Auth.** `Onboarding.dc.html` is not ported.                                                                                                                                                                                                                                                                                                                                           | Confirmed by the owner. The older 3-step flow was superseded.                                                                                                                                                                               |
| D08 | **LLM: Gemini Flash by default for every LLM feature**, through the Vercel AI SDK, called only from the server.                                                                                                                                                                                                                                                                                                                      | Low cost and a free tier. The provider and model names come from env, so self-hosters can switch. The key never reaches the browser.                                                                                                        |
| D09 | **Job sources: LinkedIn guest pages scraped with Scrapling (required), plus free and licensed APIs.**                                                                                                                                                                                                                                                                                                                                | Confirmed by the owner. See [job-ingestion.md](job-ingestion.md).                                                                                                                                                                           |
| D10 | **Scraper is a separate Python service (`apps/scraper`, FastAPI + Scrapling).**                                                                                                                                                                                                                                                                                                                                                      | Scrapling is Python-only. Keeping it behind an internal HTTP API means only the Node worker writes to the database.                                                                                                                         |
| D11 | **Google: no restricted scopes, no paid security assessment.** Sign-in uses `openid email profile`; outreach uses `gmail.send` (sensitive).                                                                                                                                                                                                                                                                                          | `gmail.send` needs Google's free verification only. See [email-and-google.md](email-and-google.md).                                                                                                                                         |
| D12 | **Interviews: browser speech-to-text, Gemini, Google Cloud TTS with free-tier tracking.**                                                                                                                                                                                                                                                                                                                                            | Owner's near-zero-cost voice spec. See [interviews.md](interviews.md).                                                                                                                                                                      |
| D13 | **Hosting: Vercel for `apps/app` (the site and the app, D21).** The worker and scraper need a container host, to be chosen later.                                                                                                                                                                                                                                                                                                    | Vercel functions are short-lived and can't run a headless browser or a long-lived queue consumer.                                                                                                                                           |
| D14 | **Cloud and local are both first-class.** Both show the same site and app (D22). `SELF_HOSTED=true` changes only how work runs: whose keys, and whether cost caps apply by default. `docker compose up` runs everything locally.                                                                                                                                                                                                     | The marketing site promises self-hosting.                                                                                                                                                                                                   |
| D15 | **Billing is not implemented yet.** Plan limits on the Pricing page are not final and are not enforced in code. Razorpay is the intended provider.                                                                                                                                                                                                                                                                                   | Owner's call. Cost guards that protect free tiers (interview session cap, TTS character counter) are separate from billing and are built.                                                                                                   |
| D16 | **License: MIT.**                                                                                                                                                                                                                                                                                                                                                                                                                    | Confirmed by the owner.                                                                                                                                                                                                                     |
| D17 | **`prototype/` is kept in the repo as the read-only spec.**                                                                                                                                                                                                                                                                                                                                                                          | UI, copy, flows and states are ported from it. Its runtime (`support.js`, `.dc.html`, `<x-import>`, `{{ }}`) never enters the real apps.                                                                                                    |
| D18 | **The main resume's content is `profiles.doc`.** The Documents editor reads and writes it; the `resumes` row of kind `main` mirrors it and holds the template, LaTeX source, ATS score and PDF. The Job Profile page keeps its own fields.                                                                                                                                                                                           | Matching, tailoring and the main resume must never disagree about what the user has done. One document, one version counter, one re-match.                                                                                                  |
| D19 | **Match breakdowns and ATS scores are rule-based code in `packages/core`; Gemini writes the prose** (match reasons, rewrites, outreach).                                                                                                                                                                                                                                                                                             | Deterministic scores are testable, free and instant, and they update live as the user edits. The LLM is used where wording matters.                                                                                                         |
| D20 | **GitHub without an OAuth app.** Reading uses the public GitHub API (optional `GITHUB_TOKEN` for a higher rate limit). Writing happens in GitHub's own UI: the profile README opens GitHub's new-file page prefilled, project READMEs are copied and GitHub's editor opened, pins open the profile's pin editor (GitHub has no pinning API). LinkedIn works from the PDF export; accepted rewrites are copied for the user to paste. | No write scopes to verify or tokens to store, and the user makes every change on GitHub and LinkedIn themselves.                                                                                                                            |
| D21 | **One Next.js app (`apps/app`) serves the marketing pages and the product.** The marketing pages are the `(marketing)` route group, prerendered as static pages; product pages are dynamic and `noindex`. One URL (`NEXT_PUBLIC_SITE_URL`), one port (4000), one deploy. Supersedes D02.                                                                                                                                             | The site and app appeared as two entities (two ports, two deploys, two URLs). One app keeps sign-in, links and self-hosting simple, and static prerendering keeps the SEO benefits of the old static export.                                |
| D22 | **Cloud and local look the same.** Nothing in the UI is hidden or disabled by `SELF_HOSTED`; it only changes processing (keys, default caps). Per-user choices live in settings, e.g. a user's own LLM key is stored encrypted in `user_settings.llm_key` in both modes instead of being written to `.env`.                                                                                                                          | The owner wants one product in both places. Differences a user can see come from their own settings, not from where it runs.                                                                                                                |
| D23 | **Settings are a dialog, not a page.** `#settings/<section>` opens it over whatever page you are on (like claude.ai/#settings/general). Account is one of its sections; Job Profile is not in it.                                                                                                                                                                                                                                    | Settings are a quick detour, not a destination. One frame keeps Account consistent with the other sections.                                                                                                                                 |
| D24 | **New accounts start on the Job Profile, not a separate onboarding.** The app stays locked until the profile is saved at 30% complete. The profile saves only on an explicit Save.                                                                                                                                                                                                                                                   | Every feature reads the profile, so it is the onboarding. An explicit save avoids half-typed data reaching matching and resumes.                                                                                                            |
| D25 | **Light and dark themes.** Same tokens, light values under `[data-theme="light"]`; choice per device (dark default, or system).                                                                                                                                                                                                                                                                                                      | Requested by the owner; the token system made it a variables-only change.                                                                                                                                                                   |
| D26 | **All Gemini calls live in `@ge/ai`, and every one has a rule-based fallback.** The app and worker pass a model from `languageModel()`; null (no key) or a failed call keeps the rules.                                                                                                                                                                                                                                              | Self-hosters without a key, and outages, still get a working product. One place holds the prompts and their schemas.                                                                                                                        |
| D27 | **Contact finding never guesses a named person's address.** It uses an address listed in the post, else the careers inbox on the company's MX-checked domain, at low confidence.                                                                                                                                                                                                                                                     | Guessed personal addresses bounce or land as spam, and hurt the user's sender reputation.                                                                                                                                                   |
| D28 | **Company boards are a curated list** (`apps/worker/src/ingest/sources.ts`, Greenhouse and Lever boards of Indian employers checked to exist), refreshed hourly. Keyword sources (Adzuna, LinkedIn) run per search.                                                                                                                                                                                                                  | Boards return every opening of one company, so a list is cheaper and more complete than searching them.                                                                                                                                     |
